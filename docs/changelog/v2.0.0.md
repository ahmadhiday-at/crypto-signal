# v2.0.0

Implementasi Operating Model dan Data Contract v2: sinyal hanya dari candle yang sudah close, status kesegaran data (`ok` / `degraded` / `stale`), penanganan error Binance yang aman, serta perbaikan keamanan API, WebSocket, dependency, dan Docker.

## ⚠️ Breaking changes

- **`/api/reset` sekarang `POST`.** `GET /api/reset` mengembalikan `405`. Request harus same-origin dan membawa header `X-Requested-With: crypto-signal`. Reset tidak lagi menghapus file; semua timeframe di-fetch ulang dan file diganti secara atomik. Respons `502` jika ada timeframe yang gagal (data lama tetap disimpan), `409` jika reset lain sedang berjalan, `429` jika kurang dari 60 detik sejak reset sebelumnya.
- **Header `Host` dibatasi.** Request HTTP/WebSocket hanya dilayani untuk `localhost`, `127.0.0.1`, `[::1]` atau nama di `ALLOWED_HOSTS`; selain itu `403 host_not_allowed`. Akses lewat IP LAN/hostname perlu ditambahkan ke `ALLOWED_HOSTS`.
- **Market State schema v2** (`/api/market/:symbol`): menambah `schema_version`, `generated_at`, `inputs`, `status`, `errors`. Arti field yang ada berubah: `price`, `ohlcv`, `indicators` dan `timestamp` sekarang berasal dari candle entry **terakhir yang sudah close**, bukan candle yang masih berjalan.
- **`/api/market/:symbol` dapat mengembalikan `503`** dengan body diagnostik (`error: "market_state_unavailable"`, tanpa field market) jika tidak ada Market State yang valid.
- **Symbol/timeframe yang tidak dikonfigurasi mengembalikan `404`.** Sebelumnya server mencoba mengambil data Binance untuk symbol apa pun di URL.
- **Format file `data/` berubah.** Snapshot per-timeframe menyimpan `candle_close_time`, `forming_candle`, `fetched_at`, `gaps`; candle memiliki `close_time`. File lama (v1) diabaikan dan di-fetch ulang otomatis saat startup.
- **Hasil scoring dapat berubah** karena perbandingan volume sekarang benar-benar memakai rata-rata 20 candle (lihat "Diperbaiki").

## Ditambahkan

- Scheduler boundary UTC tunggal (`src/jobs/scheduler.js`): berjalan 5 detik setelah setiap menit, meng-update semua timeframe yang close pada boundary tersebut, lalu membangun Market State **sekali**. Menggantikan `node-cron`.
- Engine update (`createMarketEngine`): satu update aktif per market+timeframe, build summary berurutan per market, penulisan monoton (data lebih lama tidak menimpa data lebih baru), catch-up timeframe yang tertinggal dengan throttle.
- Validasi candle (`src/services/candles.js`): baris rusak ditolak, duplikat dihapus, urutan diperbaiki, gap dihitung, candle yang masih berjalan dipisahkan.
- Model kesegaran data (`src/services/freshness.js`): input `stale` jika umur > 2 × panjang timeframe; status dihitung ulang setiap kali dibaca.
- Validasi Data Contract (`src/services/contract.js`) sebelum publish.
- Endpoint `GET /api/health`: diagnostik per timeframe, jeda Binance aktif, status stream.
- Pesan WebSocket `summary_ready`; pesan `price` sekarang juga membawa `market` dan `event_time` (aditif).
- `/api/config` menambahkan `roles` (aditif).
- Dashboard: banner status (`OK` / `DEGRADED` / `STALE` / `UNAVAILABLE`), waktu close candle dan umurnya, daftar error; nilai diredupkan jika tidak `ok`, dikosongkan jika tidak tersedia; status dibaca ulang setiap menit.
- Variabel env baru: `HOST` (alamat listen Node.js), `BIND_ADDR` (alamat publish port di Docker Compose) dan `ALLOWED_HOSTS` (hostname tambahan yang dilayani).
- Penanganan clock skew: baris terakhir respons Binance (candle yang sedang berjalan menurut Binance) tidak dianggap close kecuali sudah lewat 60 detik; snapshot dengan waktu close di masa depan tidak dipercaya.
- Test suite `npm test` (Node.js `node:test`, tanpa dependency baru, tanpa request ke Binance): 72 test.

## Diubah

- Indikator, zona S/R dan semua sinyal hanya dihitung dari candle yang sudah close. Harga live dari ticker hanya untuk tampilan.
- Dashboard tidak lagi menghitung `breakout_score` dan jarak di sisi klien saat hover; selalu memakai nilai server. Skor ditampilkan sebagai `0.00–1.00` dengan label "heuristic, not a probability".
- Header dashboard menampilkan harga live dengan label "display only"; harga close candle entry ditampilkan di banner.
- Chart menampilkan candle yang masih berjalan berwarna abu-abu; harga live hanya meng-update candle tersebut (sebelumnya menimpa candle terakhir yang sudah close di reference view).
- Stream Binance: reconnect dengan backoff eksponensial (5 s → 60 s; 15 menit setelah `451`), catch-up setelah reconnect.
- `docker-compose.yml`: port dipublish di `127.0.0.1` secara default (`BIND_ADDR`), container app di-set `HOST=0.0.0.0`.

## Diperbaiki

- Perbandingan volume di `enhanceMarketState` tidak pernah berjalan karena riwayat volume diratakan menjadi satu angka; `volume_state` selalu `normal`. Sekarang 20 volume candle close terakhir diteruskan. Rumus scoring tidak diubah (dijaga oleh regression test).
- Interval timer 1 menit di klien Binance WebSocket ditambahkan ulang setiap reconnect, sehingga update `1m` berlipat ganda.
- Cron menggunakan zona waktu lokal host; candle `4h`/`1d` tidak selaras dengan boundary UTC Binance di luar UTC (mis. WIB).
- Respons 429/418/451 dari Binance tidak ditangani khusus; request tetap dikirim pada setiap jadwal berikutnya, termasuk saat IP sedang dibatasi.
- `applyZonesToChart` memanggil `removePriceLine` pada objek yang salah sehingga refresh zona kedua melempar error.
- Garis MACD pada chart selalu 0 (field `macd` vs `MACD`).
- Border kartu Setup memakai properti CSS yang salah (`borderColorLeftColor`).
- Subscriber WebSocket yang ganti timeframe tetap terdaftar di subscription lama; dashboard tidak subscribe ulang saat timeframe diganti.
- Reset menghapus semua file sebelum fetch ulang, sehingga data hilang jika fetch gagal.

## Keamanan

- **Path traversal:** parameter URL `market`/`timeframe` sebelumnya dipakai langsung sebagai nama file (`../` ter-decode oleh Express). Sekarang divalidasi terhadap konfigurasi di API dan terhadap regex ketat di storage.
- **Operasi destruktif lewat GET:** `/api/reset` hanya `POST`, same-origin, dengan header kustom (mencegah CSRF dari halaman lain).
- **Paparan jaringan:** port Docker sebelumnya dipublish di semua interface (`0.0.0.0`) tanpa autentikasi; sekarang `127.0.0.1` secara default.
- **DNS rebinding:** allowlist header `Host` untuk HTTP dan WebSocket; reset dibatasi sekali per 60 detik agar tidak bisa dipakai untuk membanjiri Binance dari IP pengguna.
- **WebSocket:** koneksi cross-origin ditolak, payload maksimal 4 KB, maksimal 100 klien, subscription divalidasi, heartbeat untuk koneksi mati.
- **Dependency (`npm audit fix`, tetap dalam rentang semver):** `ws` 8.20.0 → 8.22.0 (high: memory disclosure, DoS), `axios` 1.15.2 → 1.21.0 (high), `proxy-addr` 2.0.7 → 2.0.8 (critical), `body-parser` 1.20.5 → 1.20.9, `follow-redirects` 1.16.0 → 1.16.2, `form-data` 4.0.5 → 4.0.6 (high). `axios` 1.21.0 membawa dependency transitif baru `https-proxy-agent` 5.0.1 / `agent-base` 6.0.2. `node-cron` dihapus (tidak dipakai).
- Header `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`; `X-Powered-By` dimatikan; pesan error API tidak lagi membocorkan detail internal.
- Dashboard membangun daftar zona dengan DOM API (bukan `innerHTML`); nilai level di reference view dipaksa menjadi angka sebelum dirender.
- Antrean rebuild summary per market dibatasi (maksimal satu berjalan dan satu menunggu), sehingga banjir request saat Binance tidak tersedia tidak menumpuk pekerjaan.

## Tindakan yang diperlukan

- **`docker compose up -d --build`** — `package-lock.json` dan `docker-compose.yml` berubah (dependency baru di image, port binding, `HOST`).
- Setelah update, port hanya dapat diakses dari `localhost`. Set `BIND_ADDR=0.0.0.0` di `.env` jika memang perlu akses dari jaringan.
- Untuk menjalankan tanpa Docker, tambahkan `HOST=127.0.0.1` ke `.env` lokal.
- Tidak perlu menghapus `data/`: file lama terdeteksi dan di-fetch ulang otomatis.
- Klien yang memanggil `GET /api/reset` harus beralih ke `POST` dengan header di atas.
- Jika aplikasi dibuka lewat IP LAN atau hostname selain `localhost`, tambahkan ke `ALLOWED_HOSTS`.

## Keterbatasan

- `qs` 6.14.2 (moderate, dipin oleh `express` 4.22.1) masih dilaporkan `npm audit`. Tidak terjangkau karena aplikasi memakai query parser `simple`; perbaikan penuh memerlukan upgrade Express.
- Endpoint tidak memiliki autentikasi; keamanan bergantung pada binding `localhost`. Menjalankan `npm start` tanpa `HOST=127.0.0.1` tetap listen di semua interface (perilaku lama dipertahankan agar container yang sedang berjalan tidak rusak).
- Script CDN (Tailwind, lightweight-charts, lucide) dimuat tanpa Subresource Integrity dan tanpa Content-Security-Policy; CDN yang disusupi dapat menjalankan JavaScript same-origin.
- Batas klien WebSocket bersifat global (100), tanpa batas per IP.
- `gluetun/wireguard/wg0.conf` di mesin lokal memiliki izin baca untuk semua user (644); disarankan `chmod 600`. Bind mount `.:/app` membuat `.env` dan `wg0.conf` terlihat di dalam container app.
- `DEFAULT_MARKET`, `DEFAULT_TIMEFRAME` dan `LOG_LEVEL` di `.env.example` tidak dibaca oleh kode (tidak diubah).
- `ROADMAP.md` memiliki dua bagian berjudul "LEVEL 2.5" (sudah ada sebelumnya).
- Container berjalan sebagai root dan image `qmcgaw/gluetun:latest` tidak dipin; belum diubah karena dampaknya pada bind mount dan VPN belum diverifikasi.
- Ambang `stale` (2 × timeframe) adalah nilai awal dan belum divalidasi terhadap pemakaian nyata.
- Kebijakan akses Binance / VPN terkait HTTP 451 belum diputuskan.
- `PROMPT_AI_*.md` belum memuat aturan "status bukan ok → WAIT" (sengaja tidak diubah).
- Uji end-to-end terhadap Binance asli melalui VPN belum dilakukan.
- Batas threshold `macd.histogram` absolut (0.1 / 0.05 / 0.02) di `enhanceMarketState` tidak diskalakan dengan harga; rumus sengaja tidak diubah.
